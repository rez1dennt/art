# Подключение отправки заявок

Интерфейс формы готов к обычной отправке. Настройка получателя выполняется на сервере; служебные пояснения в интерфейсе отсутствуют.

## Единственная настройка фронтенда

`dist/assets/contact-config.mjs`:

```js
export const contactConfig = Object.freeze({
  endpoint: '/api/contact',
  timeoutMs: 15000
});
```

Можно оставить этот адрес и реализовать обработчик на своём хостинге либо заменить endpoint адресом своего сервиса. Междоменному обработчику потребуется разрешить CORS для домена сайта.

## Контракт обработчика

Форма отправляет POST с Content-Type application/json:

```json
{
  "name": "Имя",
  "email": "name@company.ru",
  "company": "Компания или пустая строка",
  "message": "Текст обращения",
  "consent": true
}
```

Ответ после фактического принятия заявки: HTTP 2xx и JSON `{"success":true}`. Только тогда пользователь увидит подтверждение. Ошибка HTTP, некорректный ответ или таймаут показывают обычное сообщение о неудачной отправке, сохраняя заполненные поля. Повторная отправка во время ожидания блокируется.

Backend должен проверять поля и согласие, ограничивать частоту запросов, доставлять заявку выбранному получателю и возвращать подтверждение после принятия. Секреты SMTP, CRM и почтовых сервисов должны храниться только на сервере. При статическом размещении нужен отдельный серверный или serverless-обработчик.

Сам обработчик и доставка адресату в эту версию не включены: владелец решил настроить их самостоятельно. Юридические реквизиты, сроки хранения и фактические обработчики также заполняются владельцем в юридических шаблонах до публичного запуска. Из пользовательского интерфейса инструкции по настройке убраны.
